## 1. Executive Summary

To prepare for the **CORE-01 Unified Scam Detection Engine**, this document evaluates potential code overlaps, duplicate modules, and architectural seams across the repository. Recommendations are classified into 5 strict strategies:
- **REUSE**: Use existing module as-is.
- **ADAPT**: Extend existing module with new capabilities without breaking signature.
- **WRAP**: Encapsulate existing module inside a unified wrapper.
- **CONSOLIDATE LATER**: Defer consolidation until post-CORE-01 phase.
- **KEEP SEPARATE**: Maintain separation due to distinct execution contexts or security boundaries.

## 3. High-Risk Integration Boundaries

### 3.1 PII Masking Consistency
- **Constraint**: Under Rule 3 of `AGENTS.md`, raw PII must *never* be sent to LLMs or stored in server logs.
- **Seam Requirement**: Every entry point (Web form, OCR text, STT transcript, Telegram payload, WhatsApp payload) MUST pass through `maskPII()` before any downstream processing or RAG query.

### 3.2 Citation & Numerical Grounding
- **Constraint**: Under Rule 5 of `AGENTS.md`, numbers must originate from data, not LLM context memory.
- **Seam Requirement**: Return rate benchmarks and helpline numbers returned by CORE-01 must be injected directly from `data/authorities.json` and verified return data tables, not generated by LLM prompts.

## 4. Next Steps for CORE-01 Implementation
1. Keep `src/lib/detector/decision/engine.ts` as the central orchestrator.
2. Ensure input channels wrap their payloads into a common `UnprocessedPayload` interface.
3. Pass all input through standard pipeline: `Sanitize` -> `Mask` -> `Extract` -> `Evaluate` -> `Fuse` -> `Format`.
